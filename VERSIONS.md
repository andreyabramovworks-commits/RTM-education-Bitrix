# Версии RTM Education

## v52.0.5 — быстрый старт и отзывчивый интерфейс

- Тяжёлый Excalidraw runtime, его шрифты и canvas-стили исключены из стартового пути и загружаются один раз только при открытии интерактивного материала или админ-редактора.
- Ученик сначала получает компактную сводку материалов без canvas-сцен и больших HTML-полей; полное содержимое запрашивается только при открытии конкретного материала.
- Полная синхронизация продолжается в фоне, не удерживая стартовый экран и мобильную оболочку.
- Переход в админку синхронно переключает владельца интерфейса, а тяжёлые редакторы догружаются независимо от боковой навигации.
- Карточки Базы знаний, действия документа, история редакций и карточки ознакомления получили согласованные интерактивные состояния в пользовательском цвете.

Production-артефакт привязывается к commit и тегу `v52.0.5`. Откат: развернуть тег `v52.0.4`; миграция БД не требуется.

- Устранена многоступенчатая загрузка старых оболочек: пользователь видит один стабильный экран ожидания, а новый интерфейс появляется только после полной готовности стилей и runtime.
- Для разработчика возвращён доступ в админку на ПК и в мобильном меню; мобильный переключатель режима исключён.

- Профиль загружает фотографию Bitrix24, показывает очки, рейтинг пользователей и номер версии приложения.
- Цветовая схема ученика следует пользовательским настройкам оформления; кнопка синхронизации получила согласованную иконку.
- Добавлен глобальный переключатель подсказок с контекстными точками входа на основных экранах; существующая вложенная справка сохранена.

Проверки выпуска: frontend `23 passed`, backend `25 passed`, production-сборка Vite завершена, светлый интерфейс проверен при 1440×900 и 390×844. Production-артефакт привязывается к commit и тегу `v52.0.3`. Откат: развернуть тег `v52.0.2`; миграция БД не требуется.

## v51.6.0 — единый визуальный язык и стабильные назначения

- Устранено конкурирующее обновление Центра проверок: устаревший экран больше не перехватывает вкладку тестов после открытия актуального центра.

- Светлая тема больше не отменяет тематический фон: пользовательские и административные поверхности получают единый мягкий градиент, согласованные карточки, вкладки и состояния действий.
- Обновлены База знаний, обязательные документы, рабочее место проверки ответов и мастер редакций; убрано лишнее служебное сообщение над пользовательской статьёй.
- На телефоне переключатель административного режима остаётся доступным только фактическому разработчику; для остальных ролей он скрыт.
- Остановка фонового цикла загрузки устраняет периодические повторные запросы и зависание интерфейса при открытии приложения.

## v51.2.0 — управляемые кампании и системная справка

- Активную кампанию можно безопасно изменять: добавлять получателей, менять ответственных, срок и автоназначение; существующие назначения не удаляются при изменении правил.
- Для срока доступны два явных режима: только новым получателям или всем незавершённым назначениям. Срок считается в календарных днях до конца последнего дня.
- Назначение снимается отдельным действием с обязательной причиной и остаётся в истории. Кампания закрывается автоматически либо досрочно с фиксацией причины.
- В выборе получателей доступны отделы и подотделы с независимым переключателем «Включая подотделы»; у ответственных показывается роль.
- Задача Bitrix24 содержит редакцию, блок «Что изменилось» и прямую ссылку на конкретное назначение в приложении.
- Пользовательские вкладки переименованы в «Назначено» и «Пройдено», рядом добавлены «Обязательные документы» с разделами «Требуют ознакомления» и «История».
- Контекстная справка больше не создаёт шаблонные технические тексты. Связанные термины открывают вложенные карточки с сохранением контекста; на телефоне карточки складываются в компактный стек.
- Мастер редакции, кампании, карточки документов, таблицы и подсказки адаптированы для узких окон и телефонов.
- Sentry сознательно отложен на следующий отдельный этап.

Проверки выпуска: backend `22 passed`, frontend `8 passed`, синтаксис v51.2 без ошибок, production-сборка Vite завершена. Docker CLI на рабочем ПК отсутствует, поэтому локальная сборка контейнеров недоступна; её выполнит production-конвейер после публикации `main`.

## v51.0.0 — редакции документов, ознакомление и Центр проверок

- В карточку каждого документа Базы знаний добавлены редакции по датам, понятный журнал изменений и мастер обязательного ознакомления.
- Поддерживаются подтверждение кнопкой, один контрольный вопрос и существующий тест документа; свободный ответ направляется ответственному на ручную проверку.
- Назначения охватывают активных сотрудников, выбранных людей и подразделения; поддерживаются календарный срок, новые сотрудники, несколько ответственных, уведомления и задачи Bitrix24.
- Просрочка переводится в рабочую очередь и эскалируется ближайшему активному руководителю по структуре подразделений; все действия сохраняются в бессрочной истории PostgreSQL.
- «Проверка тестов» заменена единым «Центром проверок» со вкладками «Требует действий», «Тесты», «Обязательные документы» и «История», готовыми фильтрами, поиском и группировками.
- История ознакомления добавлена в персональную карточку сотрудника в Аналитике; раздел «Пользователи» переименован в «Роли пользователей» и объясняет права каждой роли.

- Исправлена прозрачность модальных окон: содержимое всегда непрозрачное, затемняется только фон.
- Google Drive OAuth является необязательным ускорителем выбора технической ревизии; при недоступности Google все поля редакции заполняются вручную.
- Добавлена Alembic-миграция `20260804_0010`; секреты OAuth читаются только из серверного окружения, а токены хранятся в БД в зашифрованном виде.

Проверки выпуска: backend `21 passed`, синтаксис v51 без ошибок, PostgreSQL SQL-миграция успешно сгенерирована, production-сборка Vite завершена.

## Откат production

Откат выполняется осознанно: сначала нужный тег переносится в `main`, после
чего обычный автодеплой развернёт его на сервере.

```bash
git fetch origin --tags
git switch main
git pull --ff-only
git revert --no-commit v47.0.0..main
git commit -m "rollback: restore v47.0.0"
git push origin main
```

Перед откатом базы необходимо проверить совместимость миграций. Резервная
копия PostgreSQL создаётся отдельно от Git и исходников приложения.

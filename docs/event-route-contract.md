# Контракт журнала событий

До переноса раздел `events` строился в `runtime-core.js` из `state.events`, `state.users`, `state.items` и `state.departments`. Он показывал дату, пользователя, событие, материал и длительность; позволял искать по пользователю, событию и материалу, фильтровать по отделу и начальной дате, обновлять данные и выгружать полный CSV. Доступ к общей ленте имели роли преподавателя, редактора, администратора и разработчика.

Теперь видимым разделом владеет `EventsAdmin.jsx`. Он получает те же поля из `GET /api/v47/events`; сервер запрещает запрос обычному пользователю. Кнопка «Все события» на дашборде открывает React-маршрут. Старый `#adminEvents`, его обработчики и отрисовка удалены. Вкладка событий внутри аналитики остаётся отдельным сценарием и пока использует старый слой.

Проверки: API возвращает имя, отдел и тип материала и отклоняет обычного пользователя; тест React проверяет фильтры и состояния экрана. Поведение в авторизованном Bitrix24 ещё нужно проверить перед публикацией.

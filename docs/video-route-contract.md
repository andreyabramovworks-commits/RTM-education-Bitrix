# Контракт экрана «Видеотека»

Экран ученика реализован в `frontend/src/VideoLibrary.jsx`, экран управления — в `frontend/src/VideoAdmin.jsx`. Оба используют авторизованный Bitrix24 запрос через `window.RTMV47.request`. Для маршрута `videos` React владеет экраном; legacy `openRoute` не вызывается. Остальные разделы админки пока используют перенесённый в React контейнер legacy DOM.

## Ученик

- `GET /api/v53/videos/library` возвращает только опубликованные видео и доступные, не архивные папки.
- При записи `POST /api/v53/videos/{id}/progress` доступ проверяется по тем же правилам, включая папку. Скрытое видео возвращает `404` и не создаёт запись прогресса.
- Существующие действия: поиск, открытие папки, просмотр видео, продолжение с сохранённого места, полноэкранный режим.

## Редактор и выше

- Экран управления использует `GET /api/v53/videos/admin` и операции над видео, папками и источниками. Право изменения проверяет backend через `require_editor`.
- Переключение в админку сохраняет живое состояние экрана ученика. При открытии видеотеки legacy маршрутизатор не должен повторно отрисовывать предыдущий раздел админки.

Перед удалением оставшихся legacy экранов нужно для каждого зафиксировать его действия, API, роли и данные, перевести действующие вызовы на React/API и проверить соседние роли в Bitrix24.

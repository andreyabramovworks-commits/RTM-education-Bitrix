# ADR 0001: единый функциональный runtime

Дата: 2026-08-06
Статус: принято для v51.4.0

## Проблема

Последовательное подключение файлов `vNNN.js` и `vNNN.css` создавало конкурирующие обработчики, повторные запросы, непредсказуемый порядок стилей и сложный откат.

## Решение

- `frontend/src/legacyRuntime.js` — единственный манифест загрузки.
- `LegacyReactHost.jsx` — единственный владелец запуска runtime.
- Код разделяется по назначению (`api`, `runtime-core`, `learning`, `acknowledgements`), а не по номеру версии.
- Новые исправления вносятся в соответствующий функциональный модуль; дополнительные версионные патч-файлы запрещены.
- Номер релиза хранится в манифесте, Git commit и теге.

## Альтернативы

Рассматривались дальнейшие точечные файлы-перекрытия и полная одномоментная миграция на React. Первый вариант сохраняет первопричину ошибок, второй слишком рискован для действующего production.

## Последствия

Runtime остаётся совместимым с текущим DOM и backend API, но получает один порядок загрузки и одну точку запуска. Дальнейшее выделение модулей выполняется постепенно с тестами контрактов.
